# Decisions

1. **Build Tooling**: Vite with vanilla TypeScript template. It provides fast HMR and a straightforward build process without unnecessary bloat.
2. **Rendering Engine**: PixiJS v8. Chosen for its WebGL/WebGPU performance, specifically for handling thousands of sprites (projectiles/particles) using ParticleContainer/instanced rendering.
3. **Testing**: Vitest for unit tests. It integrates seamlessly with Vite and supports TypeScript out of the box.
4. **Data Structures**: We use Struct-of-Arrays (SoA) typed arrays (`Float32Array`, `Uint8Array`) for entities (Projectiles, Enemies, Particles) to ensure memory contiguity, avoid GC pauses, and maintain 60 FPS budget.
5. **Randomness**: `mulberry32` is implemented for deterministic PRNG, taking a seed to ensure reproducible runs.
6. **Input**: A simple polling-based input manager that tracks keyboard state (WASD/Arrows, Shift) and pointer coordinates.

## Circuit builder rewrite

Decisions taken while rebuilding the builder (no questions were asked; each is easy to change).

7. **Default circuit needs a second turn.** The brief says Turn Right at (6,9) plus Flat+ at (9,6) reaches the ejector at (9,2), but column 10 is void, so a line turning right at (6,9) dead-ends at (10,9). The default circuit therefore also has a **Turn Left at (9,9)**. Tests and the "journey of the reference screenshot" use the same three blocks. Coordinates in the UI, the tests and this file are `(col,row)`, 1-indexed, as in the hull diagram; arrays are 0-indexed.
8. **Relative block model.** A block declares `outputs` (`F`/`L`/`R`, relative to the way the signal travels) and a packet `transform`. There are no compass ports. Straight is gone from the picker; every empty cell is an implicit straight piece. The id stays in the data only so old saves can be migrated.
9. **Orientation.** `GridCell` stores `rotation` (0/90/180/270) and `manual`. In auto mode the block's displayed orientation is derived by the compiler from the first signal that enters it (`cellInfo.effectiveRotation`); nothing is stored. Rotate buttons start from the *displayed* rotation, then set `manual`. A manual block accepts a signal only if it travels in the direction the block faces; any other side dead-ends there with a warning. Auto-orient clears `manual` and resets the stored rotation to 0.
10. **Shared cells.** Every signal is processed independently by a block, relative to its own direction. The cell's displayed orientation follows the first signal in traversal order (generators top-to-bottom, left-to-right; branches L, F, R; depth first). A signal claims the cell axis it *enters* on; a second signal entering on the same axis is cut (`lines overlap`). Different axes cross freely. Loop detection (same cell and direction twice on one signal's own path) runs before the overlap check at blocks, so a loop through plain empty cells is reported as an overlap, not a feedback loop.
11. **Segments are runs.** A straight run through empty cells is one segment (generator to the first block, or to the last cell before an obstruction). Dead-end, overlap and loop segments are stubs that end at the edge of the cell that refused the signal, which is where the cross or warning triangle is drawn.
12. **Order of operations includes chance blocks.** Packets keep an ordered list of damage operations (`add`, `mul`, `gate`). `packet.damage` is the deterministic result with gates ignored; `evalDamage` replays the list with expected values (for the stats strip) or rolled values (for `World.fire`). This is the only change to `World`: it rolls Lucky Strike, Jackpot and Gambler's Gate per projectile with the seeded combat RNG, and drops the projectile when Gambler's Gate loses.
13. **What the picker offers.** 14 of 62 blocks: Turn Left/Right, Splitter 2/3, Flat+, Percent ×, Lucky Strike, Jackpot, Gambler's Gate, Piercing, Bouncing, AoE - Circle, Shield-Breaker, Pure Converter. A block is shown only if the compiler handles it and the projectile system or `World` really consumes it (`tests/blockAudit.test.ts`). Everything else keeps `shown: false` plus a `hideReason` in `src/data/blocks.ts`. Crossover is hidden by design; `crossoverBonus()` in the same file is the hook for a future perk.
14. **Engine quirks left alone** (Rule 4): Piercing spends the damage it dealt, so it only carries on after a kill with damage left over; Shield-Breaker multiplies all direct damage by 1.5 and shields take double on top; the Armor-Piercer block emits a modifier id the engine does not read and the engine doubles all direct damage, so it stays hidden. The rule texts say exactly what the engine does.
15. **Inventory.** 20 of every placeable block. Availability is owned minus placed in the active circuit, so circuits A and B can each use the whole inventory. Removing or replacing a block returns it.
16. **History.** 50 undo/redo steps per circuit (A and B each have their own); switching A/B or hull does not enter history and starts the other side's stack fresh.
17. **Persistence.** `mgbm.builder.v2` stores only player-placed blocks per hull and slot, never the fixed hull cells, so a hull layout change can't corrupt a save. Loading validates every entry and drops what it can't use. The old `mgbm_grid` key is migrated into slot A of the Shuttle (Straight and fixed cells dropped, rotations reset, every block auto) and then removed.
18. **Input.** One `GestureTracker` turns pointer events into tap, double tap (400 ms, 32 px), drag (10 px slop), pinch, wheel, long press (450 ms) and hover, all in game coordinates via `clientToGame`. Buttons are hit-tested by the screen, not by Pixi events.
19. **Picker layout.** The sheet covers y 470-960, so the stats strip floats above it while it is open and shows the preview numbers with deltas. The grid is auto-panned to keep the target cell visible and the view is restored when the sheet closes.
20. **Tooltip ledger.** Hover (800 ms) or long-press on a cell on the line shows the packet after that cell: damage (and the average with chance blocks), pure %, projectile count and modifiers. `cellInfo.ledger` comes from the compiler.
21. **Hulls.** The ship button opens a small hull picker: Shuttle (11x11, one ejector) and Fan (9 wide, full open area, three ejectors; used for splitter and crossing tests). Each hull has its own A and B circuits.
22. **Not changed:** enemies, bosses, Fly gameplay, art. `World` still spawns every projectile at the ship's centre whatever ejector it came from, so several streams overlap on screen; the number and damage of projectiles per pulse is what matches the stats strip.

## Builder polish, chunk 1 (interaction fixes and removals)

23. **Re-tap instead of double-tap, on the grid.** One tap selects a cell (green outline, inspector text). Tapping the cell that is *already selected* opens the picker if it is buildable (`empty`, with or without a block). Generator and ejector only ever select. Void cells (and taps outside the hull) are not selectable; tapping one deselects. `BuildScreen.tapCell` is the only place that decides this. `GestureTracker` still knows double taps, but the Build screen does not pass `onDoubleTap`, so every tap, fast or slow, is a plain tap: a fast double tap is just "select, then open", nothing can open twice. Drag, pan, pinch and wheel never reach `onTap`. The selection survives closing the picker and placing a block, so one more tap on that cell re-opens the picker.
24. **Re-tap instead of double-tap, in the picker.** The first tap on a tile selects ("arms") it: inspector text and the live preview, as before. A tap on the armed tile places it (or removes, for the Remove tile) and closes the sheet. `Picker.armed` is set only by a tile tap, not by opening the sheet, so the block already in the cell is *not* armed on open; its first tap previews, its second tap closes the sheet with no change and no undo entry (`BuildScreen.placeFromPicker`). Tapping a different tile moves the arming. Tiles with none left show the "No X left" toast on the second tap. Dragging or scrolling the list does not tap. The dimmed area and the close button still close without changes.
25. **Badges and marks removed.** The green "A" badge, the padlock and the red "no signal" mark are gone with their draw functions. An off-path block is simply drawn at 50% alpha. Kept: the warning triangle on a hand-rotated block that stops a signal, the overlap/loop triangles, the dead-end cap. The inspector still says "Orientation: auto" / "Orientation: manual (facing ...)" and "No signal reaches this block."
26. **No blocked cell.** Hull cells are void, empty, generator and ejector. `parseLayout` no longer knows `X` (an unknown character still throws). Every `X` became `.`: on the Shuttle (6,1), (3,2), (5,2) and (7,2) are void. The compiler treats a signal entering void or leaving the hull as a dead end ("outside the hull"). The Shuttle diagram had been edited in the working tree to put ejectors on those cells; that edit was committed in the "checkpoint before chunk 1" commit and then replaced by the void layout above, as specified.
27. **Old saves.** Saves only ever store player blocks, never hull cells, so a stored `blocked` cell cannot reach the grid; the hull is rebuilt from the layout. `legacyCellType` in `persist.ts` maps a legacy `blocked` cell to `void`, so the old-format migration ignores it like any other non-buildable cell and keeps every block that sits on a buildable cell. Covered by a unit test and a browser test that seeds `mgbm_grid`.
