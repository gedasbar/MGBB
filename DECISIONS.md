# Decisions

1. **Build Tooling**: Vite with vanilla TypeScript template. It provides fast HMR and a straightforward build process without unnecessary bloat.
2. **Rendering Engine**: PixiJS v8. Chosen for its WebGL/WebGPU performance, specifically for handling thousands of sprites (projectiles/particles) using ParticleContainer/instanced rendering.
3. **Testing**: Vitest for unit tests. It integrates seamlessly with Vite and supports TypeScript out of the box.
4. **Data Structures**: We use Struct-of-Arrays (SoA) typed arrays (`Float32Array`, `Uint8Array`) for entities (Projectiles, Enemies, Particles) to ensure memory contiguity, avoid GC pauses, and maintain 60 FPS budget.
5. **Randomness**: `mulberry32` is implemented for deterministic PRNG, taking a seed to ensure reproducible runs.
6. **Input**: A simple polling-based input manager that tracks keyboard state (WASD/Arrows, Shift) and pointer coordinates.

## Circuit builder rewrite

Decisions taken while rebuilding the builder (no questions were asked; each is easy to change).

7. **Default circuit needs a second turn.** The brief says Turn Right at (6,9) plus Flat+ at (9,6) reaches the ejector at (9,2), but column 10 is void, so a line turning right at (6,9) dead-ends at (10,9). The default circuit therefore also has a **Turn Left at (9,9)**. Tests and the "journey of the reference screenshot" use the same three blocks. Coordinates in the UI, the tests and this file are `(col,row)`, 1-indexed, as in the hull diagram; arrays are 0-indexed.
8. **Relative block model.** A block declares `outputs` (`F`/`L`/`R`, relative to the way the signal travels) and a packet `transform`. There are no compass ports. Straight is gone from the picker; every empty cell is an implicit straight piece. The id stays in the data only so old saves can be migrated.
9. **Orientation.** `GridCell` stores `rotation` (0/90/180/270) and `manual`. In auto mode the block's displayed orientation is derived by the compiler from the first signal that enters it (`cellInfo.effectiveRotation`); nothing is stored. Rotate buttons start from the *displayed* rotation, then set `manual`. A manual block accepts a signal only if it travels in the direction the block faces; any other side dead-ends there with a warning. Auto-orient clears `manual` and resets the stored rotation to 0.
10. **Shared cells.** Every signal is processed independently by a block, relative to its own direction. The cell's displayed orientation follows the first signal in traversal order (generators top-to-bottom, left-to-right; branches L, F, R; depth first). A signal claims the cell axis it *enters* on; a second signal entering on the same axis is cut (`lines overlap`). Different axes cross freely. Loop detection (same cell and direction twice on one signal's own path) runs before the overlap check at blocks, so a loop through plain empty cells is reported as an overlap, not a feedback loop.
11. **Segments are runs.** A straight run through empty cells is one segment (generator to the first block, or to the last cell before an obstruction). Dead-end, overlap and loop segments are stubs that end at the edge of the cell that refused the signal, which is where the cross or warning triangle is drawn.
12. **Order of operations includes chance blocks.** Packets keep an ordered list of damage operations (`add`, `mul`, `gate`). `packet.damage` is the deterministic result with gates ignored; `evalDamage` replays the list with expected values (for the stats strip) or rolled values (for `World.fire`). This is the only change to `World`: it rolls Lucky Strike, Jackpot and Gambler's Gate per projectile with the seeded combat RNG, and drops the projectile when Gambler's Gate loses.
13. **What the picker offers.** 14 of 62 blocks: Turn Left/Right, Splitter 2/3, Flat+, Percent ×, Lucky Strike, Jackpot, Gambler's Gate, Piercing, Bouncing, AoE - Circle, Shield-Breaker, Pure Converter. A block is shown only if the compiler handles it and the projectile system or `World` really consumes it (`tests/blockAudit.test.ts`). Everything else keeps `shown: false` plus a `hideReason` in `src/data/blocks.ts`. Crossover is hidden by design; `crossoverBonus()` in the same file is the hook for a future perk.
14. **Engine quirks left alone** (Rule 4): Piercing spends the damage it dealt, so it only carries on after a kill with damage left over; Shield-Breaker multiplies all direct damage by 1.5 and shields take double on top; the Armor-Piercer block emits a modifier id the engine does not read and the engine doubles all direct damage, so it stays hidden. The rule texts say exactly what the engine does.
15. **Inventory.** 20 of every placeable block. Availability is owned minus placed in the active circuit, so circuits A and B can each use the whole inventory. Removing or replacing a block returns it.
16. **History.** 50 undo/redo steps per circuit (A and B each have their own); switching A/B or hull does not enter history and starts the other side's stack fresh.
17. **Persistence.** `mgbm.builder.v2` stores only player-placed blocks per hull and slot, never the fixed hull cells, so a hull layout change can't corrupt a save. Loading validates every entry and drops what it can't use. The old `mgbm_grid` key is migrated into slot A of the Shuttle (Straight and fixed cells dropped, rotations reset, every block auto) and then removed.
18. **Input.** One `GestureTracker` turns pointer events into tap, double tap (400 ms, 32 px), drag (10 px slop), pinch, wheel, long press (450 ms) and hover, all in game coordinates via `clientToGame`. Buttons are hit-tested by the screen, not by Pixi events.
19. **Picker layout.** The sheet covers y 470-960, so the stats strip floats above it while it is open and shows the preview numbers with deltas. The grid is auto-panned to keep the target cell visible and the view is restored when the sheet closes.
20. **Tooltip ledger.** Hover (800 ms) or long-press on a cell on the line shows the packet after that cell: damage (and the average with chance blocks), pure %, projectile count and modifiers. `cellInfo.ledger` comes from the compiler.
21. **Hulls.** The ship button opens a small hull picker: Shuttle (11x11, one ejector) and Fan (9 wide, full open area, three ejectors; used for splitter and crossing tests). Each hull has its own A and B circuits.
22. **Not changed:** enemies, bosses, Fly gameplay, art. `World` still spawns every projectile at the ship's centre whatever ejector it came from, so several streams overlap on screen; the number and damage of projectiles per pulse is what matches the stats strip.

## Builder polish, chunk 1 (interaction fixes and removals)

23. **Re-tap instead of double-tap, on the grid.** One tap selects a cell (green outline, inspector text). Tapping the cell that is *already selected* opens the picker if it is buildable (`empty`, with or without a block). Generator and ejector only ever select. Void cells (and taps outside the hull) are not selectable; tapping one deselects. `BuildScreen.tapCell` is the only place that decides this. `GestureTracker` still knows double taps, but the Build screen does not pass `onDoubleTap`, so every tap, fast or slow, is a plain tap: a fast double tap is just "select, then open", nothing can open twice. Drag, pan, pinch and wheel never reach `onTap`. The selection survives closing the picker and placing a block, so one more tap on that cell re-opens the picker.
24. **Re-tap instead of double-tap, in the picker.** The first tap on a tile selects ("arms") it: inspector text and the live preview, as before. A tap on the armed tile places it (or removes, for the Remove tile) and closes the sheet. `Picker.armed` is set only by a tile tap, not by opening the sheet, so the block already in the cell is *not* armed on open; its first tap previews, its second tap closes the sheet with no change and no undo entry (`BuildScreen.placeFromPicker`). Tapping a different tile moves the arming. Tiles with none left show the "No X left" toast on the second tap. Dragging or scrolling the list does not tap. The dimmed area and the close button still close without changes.
25. **Badges and marks removed.** The green "A" badge, the padlock and the red "no signal" mark are gone with their draw functions. An off-path block is simply drawn at 50% alpha. Kept: the warning triangle on a hand-rotated block that stops a signal, the overlap/loop triangles, the dead-end cap. The inspector still says "Orientation: auto" / "Orientation: manual (facing ...)" and "No signal reaches this block."
26. **No blocked cell.** Hull cells are void, empty, generator and ejector. `parseLayout` no longer knows `X` (an unknown character still throws). Every `X` became `.`: on the Shuttle (6,1), (3,2), (5,2) and (7,2) are void. The compiler treats a signal entering void or leaving the hull as a dead end ("outside the hull"). The Shuttle diagram had been edited in the working tree to put ejectors on those cells; that edit was committed in the "checkpoint before chunk 1" commit and then replaced by the void layout above, as specified.
27. **Old saves.** Saves only ever store player blocks, never hull cells, so a stored `blocked` cell cannot reach the grid; the hull is rebuilt from the layout. `legacyCellType` in `persist.ts` maps a legacy `blocked` cell to `void`, so the old-format migration ignores it like any other non-buildable cell and keeps every block that sits on a buildable cell. Covered by a unit test and a browser test that seeds `mgbm_grid`.

## Chunk 4: block plates, line endpoints, first hidden blocks

28. **Block plates.** `src/ui/blockArt.ts` draws every block as three nested sharp squares (outer grey, category colour darkened 50%, dark face), a glyph on the face and flow marks. `drawPlate(g, id, cell, rotation, outputs?)` is the only block drawing code: grid, picker tiles and the ghost use it. Glyphs live in a registry (`GLYPHS`) with `rotatesWithBlock`; routing and curve glyphs turn with the block, symbol glyphs stay upright (so Piercing, Armor-Piercer, Homing, AoE and Fork are upright). A block with no glyph gets a small centred square. Flow marks always follow the effective rotation: entry bar on the back edge, an exit triangle per output edge, both with a 1 px dark edge, drawn inside the cell (tips 1 px short of the cell edge). The ghost is the plate at 60% alpha plus the white selection-style outline.
29. **Press flash.** `UIButton.flash()` inverts a button for 120 ms; `BuildScreen.handleTap` calls it for every enabled button. Faces read `button.lit` (selected or flashing).
30. **Line endpoints.** The compiler marks segments `fromGenerator` and `toEjector` (data only, set after traversal). The drawn line starts at the tip of the generator's emitter notch and ends at the ejector bullet's flat base; the distances are `EMITTER_TIP_DIST` / `EJECTOR_BASE_DIST` in `layout.ts`, shared with the cell art.
31. **Spawn at the ejector (B0).** Each recipe's spawn point is its ejector's cell offset from the hull centre times `PX_PER_CELL` (14) in `world.ts` (`World.spawnOffsets`). Count and damage per pulse are untouched. On the Shuttle the ejector is 3 cells right of the centre, so the Fly tests that aim at a rock now aim the ejector, not the ship centre.
32. **Path and impact modifiers (B1-B6).** Numbers are constants in `engine/projectiles.ts` and scale with block level through the `level` carried in the modifier: Armor-Piercer x(1+level) against armored enemies only (the old `armor_piercer_tip` id mismatch is gone and `applyDamage` ignores unarmored targets); Curving Right 90 deg/s x level, clockwise; Homing 180 deg/s x level toward the nearest enemy within 400 px and a 60 degree total cone (+/-30 deg) ahead; Random Curve: seeded smooth noise from `rng.combat`, at most 120 deg/s; AoE Rectangle a 160x24 px horizontal bar (+40/+6 per level) hitting each overlapped enemy once; Fork on Impact: 2 copies at 50% damage (+10% per level), 0.6x size, +/-35 deg, flagged `copy` so they cannot fork, and they skip the enemy that forked them. The pool gained size, age, skipId, copy and noise fields; `ProjectileSystem.steer` runs before movement. Fly sprites follow the heading and the size.
33. **Not done in Part B:** nothing skipped, but all six blocks were implemented, tested and committed together rather than one commit each.

## Chunk 5: the economy loop

34. **One progress object.** `src/econ/progress.ts`: `mgbm.progress.v1` holds credits, owned count and level per picker block, owned hulls, best tier, best time, total kills and runs. `sanitizeProgress` validates every field and falls back to the new-game value per field, so old saves (no progress key) and corrupt data give the defaults and never throw. New game: 0 credits, Shuttle owned, Fan locked, turn_l 2, turn_r 2, flat_plus 1, everything else 0, all levels 1. `ProgressStore.commit()` saves and notifies; the Build top bar and the Shop listen to it. `src/ui/format.ts` `fmtBig` is the (new, none existed) big-number helper: 950, 9.72K, 1.23M.
35. **Tier ramp and HP.** Tier = 1 + floor(time / 15 s). Rock HP = 250 x 1.055^(tier-1) (the brief called this "already implemented", but only the constant 250 existed). `World.spawnRock` stamps the tier on the parent; children inherit it (`MitosisEnemy.tier`), so a family pays and is built at its spawn tier.
36. **Reward.** Parent reward at tier T = 7 x 1.05^(T-1) (brief: 3; raised to 7 after `npm run balance-econ` and a headless aiming bot showed only ~43 credits per default-circuit run, below the 60-90 target). The whole family (15 bodies, 4 generations) pays 1.1x the parent, split 40/30/18/12 % over generations 1-4, so a body pays 0.44 / 0.165 / 0.0495 / 0.0165 x the parent. Rewards are fractional: the run keeps the exact sum, the HUD and the summary show whole credits, and a "+N" popup appears when the running total crosses a whole credit (so tiny late-generation kills do not each print "+0"). The saved credits get `floor(run credits)`.
37. **Leaks.** A rock whose centre reaches the bottom edge is removed (no reward) and hurts the hull by 10% of max hull x size: generation 1 (large) 1.5x, generation 2 (medium) 1x, generations 3-4 (small) 0.5x. Size is by generation because every rock child had the same radius. Contact damage is unchanged.
38. **Run end.** `World.gameOver` -> 0.7 s later FlyScreen banks the run once (`recordRun`, guarded by a flag) and shows `RunSummaryScreen` (credits, kills, time, highest tier, "New best!" for tier and time, total credits). Build returns to the Build screen with the same circuit; Fly again uses `getBuilderModel()` and shows the usual "doesn't reach an ejector" toast if it can't fly. The old GAME OVER text and button are gone.
39. **Shop.** `ShopScreen`: top bar with the credit badge, inspector strip, light-grey Blocks / Hulls section buttons, a masked scrollable list of sharp rows (plate, name, owned, level, Buy and Upgrade buttons, greyed when unaffordable, MAX at the top level). Prices: copy = round(base x 1.18^owned), upgrade = round(base x 2 x 2.2^(level-1)). The tab bar is shared (`builder/tabs.ts`); Captain, Skills and Map stay "Coming soon". Hulls: Shuttle owned, Fan 600. The Build hull panel lists locked hulls greyed ("Locked: buy it in the Shop") and `BuilderModel.switchHull` refuses them.
40. **Inventory.** `BuilderModel.owned` is a live view of the progress object; `available = owned - placed in the active circuit` as before, so A and B each draw from the whole inventory. A saved circuit that uses more than is owned is trimmed on load (the last blocks in reading order are removed from both circuits of the hull, the save is rewritten) and the Build screen toasts "N blocks returned". `BuilderModel.trimmed` carries the count.
41. **Levels.** Every placed block takes its level from `progress.levels` (`syncLevels` on load, place, paste, undo/redo and after an upgrade via `refreshLevels`). Blocks whose level used to change nothing were wired: Piercing (each hit costs 1/level of the damage dealt), Bouncing (+10% damage per ricochet per level above 1), AoE - Circle (radius 50 + 10/level), Shield-Breaker (direct x(1+0.5 level): 1.5, 2.0, 2.5). The other levelled blocks (Flat+, Percent x, Pure Converter, Curving Right, Homing, AoE - Rectangle, Fork on Impact, Armor-Piercer) already scaled. Blocks with maxLevel 1 show MAX.
42. **Debug.** `?debug=1` shows a small DOM panel at the top-left of the window (it sits left of the canvas on a wide window): "+10000 credits", "Reset progress" (clears the progress, reloads; circuits are then trimmed) and "Set hull to 1" (acts on the running world through `debug/hooks.ts`).
43. **Balance.** `npm run balance-econ` prints the table; assumptions: default circuit estimated DPS, 50% of it lands (matches the headless bot), one rock family every 2 s, 60 s run with the tier ramp. Base prices are the ones in the brief (unchanged); the Fan hull stays 600. The only tuned number is the parent reward (7).
44. **Tests.** Older unit tests that need a full inventory build their model with `tests/helpers.ts` `richModel()` (20 of every block, every hull). The older Playwright scripts get the same through `rich` progress seeded by `e2e/lib.cjs` `openGame`; the economy script opens with `rich: false`. The Build "stub tab" check in `builder.e2e.cjs` now taps the Captain tab because Shop is real.

## Chunk 6a: the campaign wall engine

45. **Pure logic lives in `src/wall/`.** `constants.ts` (every number), `level.ts` (`LevelDef`, `makeTestWall`, `blockHp`, `rewardPerBlock`), `camera.ts`, `wallWorld.ts` (`WallWorld`), `sim.ts` (bot). `WallWorld` sits next to `World` and shares `ProjectilePool`, `ProjectileSystem`, the compiler and the firing code; the rest is new. Free Fly's `World` was changed only to call the shared `firePulse`/`spawnOffsetsFor` (`src/game/fire.ts`, moved out of `world.ts`; `PROJECTILE_SPEED` and `PX_PER_CELL` are still exported from `world.ts`).
46. **One hit pipeline, two target sets.** `ProjectileSystem.processHits(enemies, spatial, tier)` now builds an `EnemyField` and calls `processField(field, tier)`. A `TargetField` (`src/engine/targets.ts`) answers four questions: first target touched by a circle, targets in a circle (AoE), targets in a rectangle, targets near a point (homing); plus an optional `bounceInfo` for reflecting off a surface. `BlockField` (grid lookup: projectile position to cell index, no spatial hash) is the wall's field. `steer` accepts either an enemy array (old tests) or a field. Damage still goes through `applyDamage`, so pure damage, armor, shields, Shield-Breaker and Armor-Piercer are identical on blocks and rocks. All 172 earlier tests pass unchanged.
47. **Armor on blocks.** `armor` in a `LevelDef` cell is the raw number given to `applyDamage`. The engine's `armorScale` returns 10 (the dead code after its `return` is ignored), so armor 10 halves direct damage. `makeTestWall` uses `TEST_ARMOR = 10` and a shield of half the block's HP; 6b's generator picks its own values.
48. **Shield regeneration.** `SHIELD_REGEN_DELAY = 2 s` without a hit, then `SHIELD_REGEN_PER_SEC = 25%` of the maximum shield per second, capped at the maximum.
49. **Wall geometry.** Row 0 is the top row. `wallOffsetY` is the screen y of the wall's bottom edge (0 = the wall hangs just above the screen); row r spans `[off - (rows - r) * 54, +54)`. Projectiles and the ship use world x (0..1134) and screen y. A block's bottom edge reaching `STOP_LINE_Y` (748.8) stops the wall, clamped so it stops exactly on the line; destroying the touching blocks lowers the "lowest living block" and the wall resumes. Drain is 12% of max hull per second while touching, no i-frames; win is checked before lose in the same step.
50. **Ship vs blocks.** The pointer position is not teleported to: the ship moves toward it in steps of at most half its radius, x then y, and stops at a block face (it slides along it). A block that scrolls onto the ship pushes it out along the shortest axis (circle against box). Resolving from the pointer position instead was tried first and failed when the pointer was inside a solid wall (it oscillated between neighbouring blocks); the unit test "the ship can never overlap a block" covers it. The wall ship is clamped to world x 0..1134 and screen y 24..936.
51. **Left-edge column and the Shuttle's ejector.** The Shuttle's ejector is 42 px right of the ship and shots fly straight up, so column 0 (x 0..54) can only be hit with the ship's centre in x 0..12, i.e. the pointer in the leftmost 12 px of the screen with the camera at 0. Reachable, fiddly, left as is (a hull property; the Fan hull has ejectors on both sides). The sweeping bot dwells 0.5 s at each end for the same reason.
52. **Projectile limits in a wall.** Dropped when they leave the world sides (unless they carry Bouncing, which reflects them off x = 0 and x = 1134), when they pass 100 px above the top of the wall, below the screen bottom (+50) or after `PROJECTILE_MAX_AGE = 3 s` (1800 px of range at base speed). They are not removed at the top of the screen: shots keep flying up to blocks that are still above it.
53. **Bouncing off blocks.** Only armored blocks ricochet a Bouncing shot (as on rocks); on a block it reflects off the face it hit (`bounceInfo`), keeps its damage and gets the usual level bonus. Rocks keep the random new direction.
54. **Credits.** `rewardPerBlock(T) = 0.4 * 1.05^(T-1)`, paid per block as it dies, kept fractional like Free Fly (the HUD shows whole credits, a yellow "+N" appears when the total crosses a whole credit). They are banked once at the end, win or lose, by `WallWorld.bank()` (guarded by a flag) through the new `ProgressStore.recordWallRun({credits, kills})`: credits, total kills and run count go up; `bestTier` and `bestTime` belong to Free Fly and are untouched. Not tuned against the shop yet (a full tier-1 clear pays 67 credits, a Free Fly run about 60-90).
55. **Camera.** Starts centred (x 297), moves only horizontally, clamped to 0..594. Target speed is `edgePushSpeed(pointerX)`: 0 at the inner edge of the 18% zones (97.2 px from each side), 420 px/s at the screen edge, smoothstep in between; the camera speed follows the target with an exponential ease (rate 14/s) and snaps to 0 below 2 px/s once the pointer leaves the zone. A mouse pointer in the letterbox beside the canvas counts as the edge. Touch pushes only while pressed; with a released touch the ship and camera stay put.
56. **Rendering.** Fixed pool of 12 x 20 block views (frame, dark well, green square, shield bar sprites), only cells inside the viewport are drawn. Frame `#55555a`, armored `#d4d4d8` and twice as thick (6 px against 3), green `#6fbf73` with a side proportional to HP left (minimum 5 px), cyan bar 3 px high for the shield, 1 px gap between blocks. Stop line `#d96a5a`, 2 px at 55% alpha, 4 px at full alpha while touching. The HUD got a dim plate behind its text because grey text on green blocks was unreadable in the first screenshots. No new background art: Free Fly has none either.
57. **Run Summary wall variant.** `RunSummaryScreen` takes an optional `WallSummary`: title "Tier cleared"/"Tier failed", rows Blocks destroyed (count, percent), Time, Tier; buttons Build and Retry (same level, same circuit). Without it the screen is unchanged.
58. **Debug.** With `?debug=1` the panel gets tier, armor fraction, shield fraction, rows and "time x" inputs and a "Start wall tier" button (a test wall with 6 gaps, the current circuit or the starter circuit if it has no ejector). `debugHooks.timeScale` runs that many simulation steps per tick (1 to 60). The Build screen's FLY button is still Free Fly.
59. **Balance (placeholder).** Approach speed 26 px/s, 8 rows at tier 1. `npm run balance-wall` prints the table: with the default circuit and the sweeping bot (200 px/s) a tier-1 wall clears in 46.8 s with the hull kept full (and the bot wins with the drain on); an idle wall touches the line after 28.8 s (61% of that). Later tiers are far out of reach of the default circuit by design (HP grows 5.5% per tier, the row count 8 to 41).

## Chunk 6b: the campaign

60. **Generator (`src/wall/generator.ts`).** `generateLevel(tier)` is a pure function of the tier (seeded `Mulberry32`, results cached). Every wall holds exactly `21 * rows(T) - 6` blocks (rows from the 6a formula, 8 to 41), whatever the shape: each template is a filter over the grid, the generator grows its height until it holds enough blocks and trims the surplus from the far end. Sparse shapes therefore make taller walls (Checker 2x, Maze and Bulwark 64-76 rows). This keeps total wall HP monotone (`blocks x blockHp(T)`) so spikes and milestones are the only bumps. Block HP is still `100 x 1.055^(T-1)`; spikes multiply it by 1.6.
61. **Templates.** Eight: Slab (random 8% gaps), Pillars, Checker, Arrow, Corridor, Towers, Rings, Stairs. Tier 1 is always the Slab. A template is never used three tiers in a row. The ten milestones (10, 20, ... 100) have their own shapes outside that list (Gatehouse, Bands, Diamond, Twin Citadels, The Maze, Iron Rings, Fortress, The Funnel, Bulwark, The Last Wall) with a name and a one-sentence hint each, and are never spikes. Tier 100 is a solid wall with half the blocks armored and half shielded.
62. **Armor and shields.** None before tier 11 / 21, then a share of the blocks rising linearly from 5% to 40% at tier 100 (tier 100 itself 50%). They are clustered, not scattered: the template picks a mode (armor on the front rows, the core or the sides; shields at the back, the core or the sides) and the blocks closest to that mode get it, with some seeded noise. Armor 10 (halves direct damage) up to tier 59, 20 from tier 60; shield pool 0.5 x HP, 1 x HP from tier 60.
63. **Spikes.** Candidates are tiers 6-100 that are not milestones. Each has a seeded roll; the spikes are the candidates with roll under 1/8, clamped to 8..16 of them by taking the lowest rolls (currently 8 and 14 are the first two). The Map shows a red corner marker on spikes, even on locked tiles, so the player can see them coming.
64. **Progress v2.** Same storage key, `version: 2`. New fields: `clearedTiers` (sorted array standing for a set), `wallBestPct` and `wallBestTime` per tier (the percent is capped at 99 until the tier is fully cleared, so 100 means cleared), `medals`, `highestCleared`. A v1 save loads with all of them empty; garbage in the new fields falls back per field, medals can never exceed the cleared count. Tier N is open if N = 1 or N-1 is cleared (`isUnlocked`); clearing out of order (debug) does not open anything else.
65. **Banking.** `ProgressStore.recordWallRun` takes the campaign fields only when the level has `campaign: true` (set by the generator). Debug test walls (`makeTestWall`) keep paying credits and counting a run but never touch campaign progress. Every run pays `rewardPerBlock` for the blocks destroyed, win or lose, replays included; the Medal comes only with the first full clear. `WallWorld.medalEarned` carries it to the summary ("+1 Medal").
66. **Map.** 5 columns x 20 rows of 97 px tiles, **tier 1 at the top**: it reads like a list and scrolling down means going further. The screen opens scrolled to the next tier to play and selects it. Tiles use the block look (frame, dark face, number). Locked: dim frame and number. Cleared: yellow pip top right. Spike: red triangle top left. Next tier: thin white outline; selected tile: lighter face and thick white outline (the two coincide on the next tier). The bottom sheet shows tier, name, hint, the spike warning, the best result ("Best 100% / 0:13", "Best 4% (not cleared)" or "Not cleared") and START ("Locked" and disabled for locked tiers; tapping it toasts which tier to clear first). The Map tab of the tab bar opens it too, and the Build screen has a CAMPAIGN pill above FLY. FLY is still Free Fly.
67. **Wall summary buttons.** Campaign clear: Next tier / Map / Build (Retry instead of Next on tier 100); campaign fail: Retry / Map / Build; debug test walls keep Build / Retry. `WallSummary` now carries a list of buttons.
68. **Edge columns.** The ship is clamped to `reachMin..reachMax` (the wall width widened by the ejector offsets: -42 to 1134 on the Shuttle) and the camera range is widened the same way (-42 to 594). With the camera at an end, the ejector (not the ship centre) can sit on world x 0 or 1134: pointer 0-54 px reaches column 0, pointer 444-498 reaches column 20 at the right end. The extra 42 px beside the wall is just empty space. Replaces the "left as is" of decision 51.
69. **Pacing, no retuning.** `npm run balance-wall` now prints the real levels: needed DPS = effective wall HP (armored blocks count double, shields added) / 60 s, against the starter gun's estimated 404 DPS. The ratio runs 0.67 (tier 1), 0.94 (5), 1.5 (10), 3.6 (20), 8.5 (30), 37 (50), 282 (75), 1769 (100): about 9% a tier from the start, smooth, with armor and shields adding a few percent from 11 and 21. Spikes stand out (tier 8: 1.96 against 1.16 and 1.42 around it). Tiers 5-15 rise x2.6 against x2.2 for 1-10, which I judged not a jump, so HP growth and row growth are unchanged. The idle time to the stop line is the same 28.8 s for every tier (approach speed is still one constant). Cumulative credits from clearing all earlier tiers once: 849 before tier 10, 2873 before 20, 31167 before 50.

## Chunk 6c: carve a path, one-hit ship

These replace the stop line, hull drain, solid-ship and "wall resumes" rules of decisions 49, 50 and 55 (6a) and the win/lose handling of 54/57/67 for every wall, campaign or debug. Free Fly is unchanged except the ejector offset.

70. **Rules.** The wall always approaches (`approachSpeed`, one constant per tier) and never stops. The ship moves exactly where the pointer asks and is not blocked. A run ends in one of three states: `cleared` (the last block destroyed; beats the other two in the same step), `crashed` (the ship's hit point, a 7 px circle, overlaps the cell of a live block; checked after the shots of that step, so a block destroyed this frame never kills; a damaged block still does) or `passed` (ship y above the finish line, which sits 1.5 cells beyond the last row; with 0 blocks alive that moment it is a clear). The drawn dot stays 10 px. The stop line, drain, hull, solid-block push-out and sliding movement were deleted with their tests.
71. **Boost.** `scrollSpeed(base, shipY)`: base at y >= 0.35 x height, rising linearly to 4 x base at y = 0 (`TOP_ZONE`, `BOOST_MAX` in constants). The ship is clamped at 24 px from the top, so the practical maximum is 3.8 x. Projectile speed unchanged.
72. **Ejector offset.** `FIRE_OFFSET_SCALE` multiplies every ejector's x/y offset from the ship centre, in Free Fly too (`spawnOffsetsFor`). **I used 0.25, not the 0.35 of the brief**: with 0.35 the Shuttle ejector sits 14.7 px from the dot and 14.7 + 7 = 21.7 is not less than CELL/2 - 8 = 19, so the unit test the brief asked for could not hold. At 0.25 it is 10.5 px (17.5 < 19). Existing tests/e2e that assumed 42 px (hiddenBlocks, browser and economy scripts) now use the scaled value. The camera range is again 0..594 and the dot range 0..1134 (the 6b widening is gone): the dot at world x 0 puts the ejector at 10.5, inside column 0; the dot at 1114 does it for column 20.
73. **Generator guarantees.** Every column holds at least `ceil(0.3 x median column)` blocks (`MIN_COLUMN_SHARE`), spread over its height, so no straight lane is open and none is nearly free; surplus is trimmed from the far end without taking a column under its minimum. This replaced the 6b "one block in an empty column" rule and fixed the cheap lanes the pacing table showed (Stairs 1-11% of the median column, Pillars 2-14%, Corridor 1-15%; now the lowest is 14%). The wall always starts with its bottom edge at y 0, 768 px (14 cells) from the ship's start, so the first row is at least 6 cells away; a unit test checks it with the lowest non-empty row. Block count can exceed `21 x rows - 6` by a few blocks.
74. **Results and progress (save version 3).** New: `passedTiers` (a pass or a clear; always a superset of `clearedTiers`; unlocks the next tier), `wallBestClearTime`. `wallBestPct` (capped at 99 unless cleared) and `wallBestTime` (now of passes and clears) are per tier. A v2 save loads with `passedTiers = clearedTiers`; the storage key is unchanged. Credits are paid for every destroyed block in any run. Only the first full clear gives a Medal.
75. **UI.** HUD: Credits, Tier (red SPIKE), name, "Destroyed X%" and the right-edge bar, which now shows how far through the wall the ship is (`WallWorld.progress`: 0 at the start position, 1 at the finish line); no hull bar. Debug walls use the same HUD. A thin white line marks the finish. Summary titles "Tier cleared" / "Tier passed" / "Crashed"; rows Destroyed (percent and count), Time, Result (Cleared / Passed / Not passed); a crash waits 0.3 s before the summary, a pass or clear 0.6 s. Buttons: Next tier (Retry on tier 100) / Map / Build after a pass or clear, Retry / Map / Build after a crash; debug walls Build / Retry. Map: hollow yellow pip = passed, filled = cleared (Medal); inspector "Best destroyed 94%  ·  Passed 0:42" / "Cleared 0:42" / "Not passed"; locked-START toast says "Pass tier N first".
76. **Bots.** `CarveBot`: while the wall is still above the screen it picks the column with the lowest effective HP (shield + HP x (1 + armor / 10)), then stays just under its lowest live block (margin 16 px), climbing as blocks die and flying up the lane when it is clear, never entering a live block; pilot speed limited to 700 px/s. `ClearAllBot`: parked at the bottom, always aims at the column whose lowest block hangs lowest. `simulateWall(level, grid, 'carve' | 'clearAll')`.
77. **Pacing (`npm run balance-wall`).** The starter gun (est. 404 DPS) passes tiers 1-10 with the carver by large margins (needed DPS 0.04-0.22 of it) and clears tier 1 in 44 s with the clear-all pilot against 35.7 s before the first row reaches a ship at the bottom (needed 1.12 x the estimated DPS: possible, demanding). Tier 2 and later are not clearable by the starter gun with that pilot. Tier 100 needs 91 x the starter DPS to pass. Constants (HP growth, rows, base speed 26) were not retuned.

## Chunk 7a: Free Fly wrap-around world and spawn safety

78. **Cylinder.** `src/engine/wrap.ts`: `FREE_FLY_WORLD_SCREENS = 3`, `WORLD_W = 1620` (the wall's own width stays `WORLD_WIDTH`), `wrapX`, `wrapDx(a, b)` (shortest signed delta from b to a, in [-W/2, W/2)) and `wrapDist`. The shared engine code is wrap-aware only through an opt-in width, so the wall keeps its plain maths: `ProjectileSystem.wrapW` (homing), `EnemyField(…, wrapW)` (hit, circle AoE, rect AoE), `MitosisSystem.wrapW` (spawn and children fold into the world), `SpatialHash(…, wrapW)` (cell size is stretched so a whole number of columns fills the world, columns are taken modulo that count, queries near the seam look at the far side). `World` sets all of them to `WORLD_W`; `WallWorld` leaves them at 0. Free Fly projectiles wrap in x instead of bouncing off the sides, and now also end after `PROJECTILE_MAX_AGE` (3 s, the wall's cap): an E/W ejector would otherwise circle the cylinder forever.
79. **Camera.** `WallCamera` got a third argument `wrapW`: with it there is no clamp, `x` wraps into [0, W) and `travel` is the unwrapped distance (the e2e asserts `travel > WORLD_W`). Same edge-push constants. `World` owns it (`world.camera`), so the sim, bots and tests share it. **`camera.x` is the viewport's left edge** (as in the wall; ship world x = camera x + pointer x). The brief's render formula `wrapDx(x, camX) + viewport/2` means a camera *centre*, so the screen x is `wrapDx(x, camX + viewport/2) + viewport/2` (`World.screenX`). With W = 3 viewports an entity is within W/2 of the centre on exactly one side, so there is never a duplicate or a pop at the seam; sprites further than 60 px beyond the screen are hidden. The camera starts at 0, so the first frame looks like the old fixed screen.
80. **Backdrop and seam.** Free Fly had nothing to show sideways travel, so there are faint vertical rules every 90 px of world x (1620 is a multiple of 90, so they are continuous over the seam). `?debug=1` adds a faint rose line at world x = 0. Free Fly has no right-edge scroll bar (only the wall has one), so there was none to adapt and none was added.
81. **Leash (`game/leash.ts`).** Distance is the wrapped Euclidean distance to the ship. Beyond 1.2 viewport widths for more than 4 s a rock heads for the ship at its own speed (`ENEMY_SPEED` 40 px/s, no sway); it keeps being pulled until it is within 0.9 widths (`LEASH_RELEASE`), otherwise it would hover on the leash edge. Beyond 1.5 widths for more than 10 s (its own timer, `farT2`) it is moved back to the spawn ring: same id, type, generation and HP, so the same HP fraction. **Geometry note:** with a 3-screen world the farthest a rock can be in x is W/2 = 1.5 widths, so "beyond 1.5 widths" can only happen through the y offset (a rock far above or below the ship). The respawn rule is a safety net for that; the 1.2-width pull is what does the work sideways. The unit test parks a rock at W/2 to the side and 300 px above the screen (2.2 widths away).
82. **Spawn ring and leaks.** Rocks spawn every 2 s just off-screen, 45% above the top edge across the width, the rest beside the view in its upper 55%, 30 to 110 px out, in wrapped x. The ring is placed around the *view* (camera), not the ship: a ship at the screen edge would otherwise get rocks spawned on-screen. Everything is within about 650 px of the ship, inside the 1.2-width leash. A rock that falls past the bottom edge while it is **off to the side** is not a leak (nobody saw it): it costs no hull and goes back to the ring. On-screen leaks hurt as before.
83. **Spawn safety (`engine/control.ts`).** `PointerGate` remembers the pointer's first reading after the run started (where the player tapped the button is not a move) and fires on the first change of position or a new press. Until it fires `World` and `WallWorld` (built with `safeStart: true` by the two screens) keep the ship at its start spot (Free Fly: screen x 270, y 768; wall: world centre, y 768) and ignore the pointer; **the camera does not push either**, so a pointer parked at the edge does not scroll the level. After it fires, `beginControl()` eases the ship from where it is to the pointer with a smoothstep over `EASE_TIME` (0.25 s), then it follows exactly. The 1.0 s `GRACE_TIME` invulnerability starts with it: Free Fly skips contact damage and knockback (it reuses `World.invuln`, so the existing blink shows; a hit still gives 0.5 s afterwards); the wall skips the crash check (`WallWorld.invuln`, new blink in `WallScreen`). A block under the ship when the grace ends crashes it on that step. **Without `safeStart` (the default, used by the older unit tests) control is immediate and there is no grace**, so tests that drive the ship by hand are unchanged.
84. **Old scripts.** `e2e/lib.cjs` launches Chromium from `CHROMIUM_PATH` or `/opt/pw-browsers/chromium` when Playwright's own download is missing. `wall.e2e` waits 450 ms for the ease before reading the boost and no longer expects progress to be exactly 0 (the finish line approaches a ship that now starts at 768, not 800). `campaign.e2e`'s crash step zeroes `wall.invuln` after the first move (the grace is covered by the unit tests). `browser.e2e` accepts the dimmed ship green while it blinks.

## Chunk 9a: blocks batch 1 (12 new blocks) and real upgrade levels

104. **Audit (step I0).** `scripts/block-audit.ts` now also prints the implementation status of the hidden blocks. Of the 42 hidden blocks, 2 were fully implemented (the generator and ejector hull cells, which are not placeable) and 40 were stubs: 26 compiler-only (a transform that only tags the packet, nothing in the engine reads the tag) and 14 data-only (no transform at all; 7 of them passive blocks). None of my 12 was implemented, so none was kept and none was swapped: the only new mechanic is per-pulse state (see 105), which four blocks share and which came to about 150 lines. `MGB_Mitosis_game_prompt.md` is not in the repository, so the master catalogue was not available; no swap was needed.
105. **Per-pulse state: the `Gun` (`game/fire.ts`).** The compiler stays a pure function. Stateful blocks add stages to the packet's damage ops (`oc`, `cap`, `alt`, `delay`) and the `Gun` walks a recipe's ops in path order each pulse with per-recipe state (a Float64Array, three numbers per op). A recipe without such ops takes the old path unchanged (same `rng.combat` call order). `World` and `WallWorld` own a `Gun`, call `gun.update(dt, ship)` before the pulse loop (releases delayed shots, advances the clock) and `gun.fire` per pulse; `fire.ts` keeps `firePulse` as a thin stateless wrapper.
106. **Level convention.** Level 1 is the value in the brief; every listed increment is added per level ABOVE 1 (Alternator x2.0 at level 1, x2.1 at 2). All twelve new blocks have `maxLevel` 5. The numbers live in `engine/effects.ts` and the inspector texts read the same functions.
107. **Alternator.** Outputs L and R; each output's packet carries `(block cell, branch)`. Per pulse the gun reads the block's counter once (all recipes below the same block see the same value), lets the recipe whose branch matches fire, and counts the pulse only if some recipe reached the block. The damage multiplier (2.0 + 0.1 per level above 1) is applied at compile time to both outputs. A branch that dead-ends still takes its turn (that pulse fires nothing), because the packet really goes there.
108. **Capacitor.** Absorbs 3 packets (per recipe) and emits one at the sum of their damage at that point in the path, x(1 + 0.1 per level above 1). Blocks after the Capacitor act on the sum; chance gates before it are rolled per packet and summed. Emits every 3rd pulse.
109. **Overclock.** Per recipe: the n-th consecutive packet (n from 0, so the first of a streak is unboosted) gets x(1 + min(1.0, gain n)), gain 2% + 0.5% per level above 1, so the cap is reached after 50 packets at level 1. The streak resets after `max(1 s, 1.5 pulse periods)` without a packet (the Dart fires once a second and its frame jitter would otherwise reset it every time). It multiplies at its place in the path like Percent x does, so a Flat+ after it is not boosted.
110. **Delay Line.** 0.1 s x level, summed along the path. The packet's damage is decided at the pulse; the projectile is created at the ship's position when the delay ends (a 512-entry ring, no allocation). Rate of fire is unchanged.
111. **Executioner, frozen bonus.** Applied in one place (`ProjectileSystem.strike`), for every damage source of the pipeline (hit, AoE, chain; a burn tick takes the frozen bonus too): x3.0 (+0.25 per level above 1) against a target with HP strictly below 25% of max HP before the hit; frozen targets take x(1 + bonus) from everything. Both work on rocks and wall blocks.
112. **Chain Lightning.** From the target that was hit, up to 2 (+1 per 2 levels above 1: 2, 2, 3, 3, 4) jumps to the nearest living target not yet in the chain, by centre distance, within 150 px; each takes 70% of the ORIGINAL hit damage (not compounded). The search is `TargetField.collectCircle`, so on the wall it finds blocks. Chain and AoE victims also receive the statuses of the projectile. Arcs are a ring of 48 in `ProjectileSystem` (0.12 s); each screen redraws one pooled Graphics from it.
113. **Boomerang.** 250 px (+75 per level above 1) out, then it homes on the ship's current position at the original speed and is removed within 18 px of it. It survives hits (the target it just hit is skipped until it turns round, so each leg hits a target once). AoE detonation still removes it.
114. **Orbit.** Opens from the ship to radius 60 over 0.12 s, circles clockwise at the projectile's own speed (10 rad/s), for 1.0 s (+0.5 per level above 1), then flies off in its original direction. Positions are set through the velocity (`v = (target - position) / dt`) so the worlds' movement code is untouched. Hits do not remove it; each target is remembered for 0.3 s (a ring of 4 per projectile). Its projectile age counter restarts at launch, so a 3 s orbit survives the wall's 3 s age limit.
115. **Mine.** Flies 220 px (+40 per level above 1), stops exactly there and waits up to 12 s (age counter held at 0 so the wall's age limit does not take it); size x1.3. Any touch is a normal hit at full damage and removes it (so AoE blocks on the same packet make it an explosion). Free Fly: rocks drift into it. Wall: x is world x, y is screen y, so the wall runs into it. Combos: Orbit first, then Mine or Boomerang (Mine wins over Boomerang); fork copies fly plain.
116. **Ignite.** The burn is 30% (+10% per level above 1) of the hit damage after bonuses per second for 3 s, applied in ticks every 0.5 s; the part of a tick left when it ends is paid, so the total is exactly rate x duration. It ignores armor and shield (true damage). A new hit sets the timer back to 3 s and keeps the larger rate: it does not stack. Burn ticks reach the hit callback as `kind = 1`; Free Fly draws them as small orange numbers (11 px). **The wall has no damage numbers at all, so there is nothing to show there.** A burn tick does not flash a block or hold back its shield regeneration.
117. **Corrosion.** Each hit takes 5% of the armor left, never below (1 - cap) of the original armor, cap 50% (+10% per level above 1). `armor0` is remembered on the target at the first corrosive hit. The wall draws an armored block's frame thickness 3 + 3 x (armor / armor0) px and fades its colour the same way, so a stripped block has a thin dim frame.
118. **Frostbite.** Slow 30% (+5% per level above 1) of the rock's whole drift for 2 s (+0.5), +25% (+5%) damage from everything. **Rocks do not rotate in this game, so "drift and rotation" is drift only**; wall blocks do not move, so there only the damage bonus applies. Tints: a rock burns red-orange (`0xff4a1a`; the plain rock is `0xffa500`, so a faint tint would not read), frozen is pale blue; a wall block gets a 42% alpha orange or pale-blue wash.
119. **Stats strip (I4).** Each recipe has a share of pulses it fires on: 1/n per Capacitor, 1/2 per Alternator branch. Proj/pulse = sum of the shares divided by the most frequent recipe's capacitor share; Pulses/s = base pulses x that share (a Capacitor lengthens the interval: 1.33/s with one Capacitor on the Twin); Dmg/shot = share-weighted average damage of a projectile; Est. DPS = sum of share x expected damage x base pulses. Overclock enters at its average over an unbroken 60-packet streak (x1.575 at level 1); Capacitor multiplies the packet by 3 x its bonus; an Alternator's two branches add up to one projectile per pulse at x2.0; Delay Line changes nothing; Executioner, the statuses, Chain, Boomerang, Orbit and Mine change nothing (the estimate is blind to what happens to the target).

Delay Line, Overclock, Boomerang, Mine, Ignite uncommon; Alternator, Capacitor, Executioner, Orbit, Frostbite, Corrosion rare; Chain Lightning epic. Upgrades follow the unchanged formula base x 2.0 x 2.2^(level-1) from the same base. Every new block has `unlock: 'shop'`; `unlock: 'map'` is read by the Shop (such a block would not be sold) and nothing else yet.

Max level and scaling: Turn Left/Right 3 (+10% projectile speed per level above 1); Splitter 2/3 5 (each copy x(1 + 0.05 per level above 1)); Lucky Strike 3 (33/38/43%); Jackpot 3 (4/5/6%); Gambler's Gate 3 (50/55/60%); Random Curve 3 (max turn rate x(1 + 0.25 per level above 1)); Piercing 3 -> 5 (its existing 1/level cost formula); Flat+ and Percent x 10, Homing, AoE Circle, AoE Rectangle, Bouncing, Pure Converter 5, Shield-Breaker, Fork, Armor-Piercer, Curving Right 3 as before. The builder save already validates block levels against `maxLevel`.

## Chunk 11a: blocks batch 2 (mitosis-aware blocks + 3 others) and the Bouncing fix

148. **Audit (L0).** `scripts/block-audit.ts`: all 9 blocks were hidden compiler-only stubs (a transform that only tags the packet; nothing in the engine read the tag): the six Mitosis ones, Gravity Well, Static Charge and Random Router (which was a fixed 1/3 split, hidden because it would duplicate Splitter 3). None needed a large new system; the new state is five optional fields on a target (`EnemyEntity`: generation, cauterize, fission, spill, static count), two small ring buffers in `ProjectileSystem` (Residue clouds, Gravity Well attractors, drawn by `ui/fieldFx.ts`), a `rnd` stage in the Gun, and `World.applyFission`. The mitosis system already had `forceSplit`, `isFissionCatalyst` and `cauterizedTimer`; they were unused and are now reached.
149. **Generations.** In the real data a parent rock is generation 1 and its first children are generation 2 (the brief's "generation 0 parent / >= 1 fragment" does not exist: chunk 10a, decision 128). Cleaver: generation 1 = parent (x0.75), generation >= 2 = fragment (x1.5), so Swarm pebbles (generation 3) and Brood count as fragments. Wall blocks have no generation: the rock-only blocks do nothing there.
150. **Per-level numbers (level 1; each + per level above 1).** Fission Catalyst cooldown 1.0 s (-0.1, floor 0.4). Cauterize 3 s (+0.5), +25% credits (+5%). Cleaver x1.5 (+0.1) / x0.75 (+0.05, capped at 1). Culling Bolt 4% of max HP (+1%), cap 6x the shot. Residue Seed 15% of the killing hit per tick (+5%), radius 40 px, 2.5 s, tick 0.5 s. Overkill Spill 50% (+10%, max level 6 so it reaches 100%). Gravity Well pull 120 px/s (+40), radius 120 px, 1.5 s. Static Charge pulse 150% (+25%), 3 hits within 2 s. Random Router: both-outputs chance 0% (+10%). All maxLevel 5 except Overkill Spill (6). All numbers are in `engine/effects.ts` and the inspector text reads the same functions.
151. **Fission Catalyst.** Acts on a hit that does not kill, after all hits of the step (`World.applyFission`): the rock must have a split rule it can still use (generation cap 4 and the species' `maxGeneration`), must not be cauterized (Cauterize wins over Fission, also within one shot) and must be off cooldown. Children share `hp / n` (the existing `isFissionCatalyst` path) and start on the cooldown (the "per-rock" cooldown lives on the new rocks, since the parent is gone). No kill, no credits: the parent's share of the family reward is not paid, and total remaining HP shrinks (children total the parent's remaining HP, not 1.1 x max HP): it trades credits for speed. Darter and Budder have no split rule: nothing happens (counter `fissionBlocked`).
152. **Cauterize.** The mark is set on any hit, a lethal one included, so a one-shot kill with the block already leaves no children. The +credits apply only if the rock would have split (it has a split rule it can still use); the children-cancel is the mitosis system's existing `cauterizedTimer` rule.
153. **Culling Bolt** adds `min(pct x maxHP, 6 x packet damage)` to the hit before the other multipliers (it never weakens a shot). **Overkill Spill:** rocks ALREADY pass 100% of a killing hit's excess to their children (chunk 10a, `handleDeath(e, -e.hp)`; large excess even removes the children without paying for them). That baseline cannot change, so the block deals its share of the excess to the children ON TOP, as damage after the split (a child at 0 HP dies next step and pays like any kill). The inspector says so ("on top of the 100% a split already passes on").
154. **Residue Seed.** A kill by a projectile hit, chain jump or Static pulse leaves a cloud; cloud ticks and burns do not (no chain reaction). A tick hurts every living target whose shape touches the 40 px circle (armor and shield apply, nothing else), shows as a small number in the Mitosis colour and does not flash or hold back a shield. The cloud is fixed in the world: rocks drift out of it (they fall at 40 px/s), a scrolling wall moves it with the wall (`shiftClouds`). Drawn as two thin 12-sided outlines (no fill, no glow): the outer ring fades in its last 0.5 s, the inner one shrinks over its life.
155. **Gravity Well.** One attractor per impacting projectile (a ring of 16: the oldest is replaced). Each step every rock within 120 px moves towards the point at the well's speed, never past it; the point is clamped to the screen (x in [0, 540], y >= 0), and the normal confinement still runs after it, so a rock cannot leave the screen (tested: 120 s with wells on rocks at the sides and above the top, plus the old property test). Rock-only; a wall ignores it.
156. **Static Charge.** Count per target (`scN`, window from the first counted hit, 2 s); the 3rd hit releases a pulse of 150% of that hit's damage (after Cleaver/Culling/Executioner/frozen, through armor and shield) and resets the count; the pulse does not count itself. Applies to rocks and wall blocks (any target object).
157. **Random Router.** `BlockDef.router`: the compiler puts a `rnd` stage on each output branch (like Alternator's `alt`); the Gun picks once per pulse per router from the seeded combat RNG (`rng.combat`), shared by every recipe below it: 50/50 left or right, or (chance `routerBoth(level)`, 10% a level above 1) both. Two outputs only (L and R) at every level: a third forward output would need level-dependent outputs in the compiler and the plate art; the "control" the level buys is the both-outputs chance instead. Stats: each branch fires `(1 - both)/2 + both` of the pulses, so Proj/pulse is 1 + both and Est. DPS rises with it.
158. **Bouncing fix (L1b).** The projectile carries `bounces` (pool field, -1 = none; 2 at level 1, +1 per level). A hit that would consume it (no Piercing, or Piercing used up) instead reflects it off the contact normal (rocks: from the rock's centre; wall blocks: the face), adds +/-35 degrees of seeded spread (turned the other way if it would aim into the surface), keeps speed and damage, and skips the target it just hit until it hits something else. Piercing first: a pierce that leaves damage keeps flying and keeps its bounces; one that would be used up becomes a bounce with the pre-hit damage restored. The old per-level "+10% damage per ricochet" and the armored-only rule are gone (level-1 damage is unchanged; the level-3 text said +20%; `bounceDamageMul` removed, its tests updated). Edges: Free Fly now bounces off the four screen edges (no damage, costs a bounce); a flat (non-ring) wall's side edges also cost a bounce (before: unlimited); ring walls have none. A shot carrying Bouncing is freed at `PROJECTILE_MAX_AGE` (3 s) in Free Fly too (the wall already did). The hit flash is the existing one on the target; no new effect. A spread is not clamped to the first heading, so headings drift over several bounces; speed never changes, so a shot never sits still.
159. **Tests.** `tests/blocks11a.test.ts` (one test per block + 7 for Bouncing); old tests moved with the rules they asserted: the wall test "a plain block stops it" now says the plain block bounces it, the picker is 41 blocks in 5 sections, `bounceDamageMul` is gone. Mutation check (5): Bouncing count, Fission cooldown, Culling cap, Static Charge hit count, Cleaver generation threshold: each failed its own test (`reports/chunk11a/mutation-check.txt`).
